Консольный cheat engine с основным функционалом. Был написан для практики в языке C/C++

## Следующий текст был написан используя ИИ, чтобы ускорить процесс написания документации к проекту

Консольный сканер и редактор памяти процессов для Windows — упрощённый аналог Cheat Engine. Написан на C/C++ для практики в работе с WinAPI, памятью процессов и многопоточностью.

Программа подключается к выбранному процессу, ищет в его памяти значения нужного типа, позволяет отфильтровать результаты несколькими повторными сканированиями, изменить найденное значение, «заморозить» его (постоянно перезаписывать) и сохранить найденные адреса в файл.

Найденное значение можно один раз сохранить через пункт 10 — после этого при каждом запуске игры программа сама находит его по цепочке указателей, без сканов.

## Возможности

- **First Scan** — первичный поиск значения в памяти процесса с выбором типа данных: `short` (2 байта), `int` (4 байта), `float` (4 байта), `double` (8 байт), `byte` (1 байт), `int64` (8 байт). Сканируются выделенные регионы памяти, доступные на запись (включая copy-on-write страницы модулей, где лежат статические переменные). Поиск идёт по выровненным адресам, как «Fast scan» в Cheat Engine.
- **Unknown initial value** — поиск, когда значение не видно (полоска здоровья, выносливость). Вся память запоминается во временный файл в `%TEMP%`, дальше отсеиваешь через Next Scan: *Increased*, *Decreased*, *Changed*, *Unchanged*. Когда адресов становится меньше 5 миллионов, программа переходит на обычный список, а файл удаляется.
- **Next Scan** — повторная фильтрация уже найденных адресов по условиям: увеличилось (*Increased*), уменьшилось (*Decreased*), точное значение (*Exact Value*), изменилось (*Changed*), не изменилось (*Unchanged*). Адреса, которые перестали читаться, отбрасываются.
- **Change value** — запись нового значения по выбранному адресу. Если адрес заморожен, заморозка продолжает держать уже новое значение.
- **Freeze value** — «заморозка» значения: фоновый поток каждые 50 мс перезаписывает все замороженные адреса. Замораживается текущее значение или то, которое введёшь. Заморозка не зависит от результатов скана: после нового First/Next Scan или загрузки из файла замороженные адреса продолжают работать.
- **Unfreeze value** — снятие заморозки с выбранного адреса.
- **Show found addresses** — список найденных адресов с текущим и предыдущим значением (показываются первые 100).
- **Save / Load addresses** — сохранение найденных адресов в файл `adres.txt` и загрузка их обратно.
- **Save found value permanently (pointer scan)** — для найденного адреса программа сама ищет цепочку указателей от статического адреса (внутри exe/dll) и сохраняет значение в таблицу под твоим именем. Работает с 64- и 32-битными играми.
- **Table** — таблица сохранённых значений игры («Деньги», «Здоровье»…). Адрес каждого значения находится по цепочке указателей при каждом запуске игры. Значения можно менять и замораживать; заморозка запоминается в файле и включается сама при следующем запуске.
- **Автоподключение** — если для запущенной игры уже есть таблица, программа предлагает подключиться к ней сразу. Если игра закрылась, программа может дождаться её перезапуска и подключиться снова.

После каждого скана печатается статистика: сколько найдено, сколько мегабайт прочитано, сколько было вызовов `ReadProcessMemory` и сколько времени это заняло.

Для `float` и `double` точность поиска берётся из того, как введено число: `100` найдёт всё от 99 до 101 (например, `99.73`), `12.5` — от 12.4 до 12.6, `12.55` — от 12.54 до 12.56. Игра часто показывает округлённое значение, а в памяти лежит дробное, так что вводи столько знаков, сколько видишь на экране. Дробные числа можно вводить и через точку, и через запятую.

## Структура проекта

Проект разделён на две части: **core** — работа с памятью (ничего не печатает и не спрашивает у пользователя), **ui** — консольный интерфейс поверх core. Благодаря этому к ядру позже можно прикрутить другой интерфейс (например, GUI) без переписывания логики.

```
cce/
├─ main.cpp                 # точка входа: список процессов, выбор PID, запуск меню
├─ src/
│  ├─ core/
│  │  ├─ Win.h              # подключение windows.h + UniqueHandle (RAII-обёртка над HANDLE)
│  │  ├─ Value.h/.cpp       # типы значений (ValueType), Value, разбор и форматирование
│  │  ├─ Process.h/.cpp     # список процессов, открытие, чтение/запись памяти
│  │  ├─ Scanner.h/.cpp     # First Scan, Unknown initial value и Next Scan
│  │  ├─ Freezer.h/.cpp     # заморозка значений (один фоновый поток)
│  │  ├─ AddressFile.h/.cpp # сохранение/загрузка адресов
│  │  ├─ Pointer.h/.cpp     # цепочка указателей: разбор, печать, вычисление адреса
│  │  ├─ PointerScanner.h/.cpp # pointer scan
│  │  └─ Table.h/.cpp       # таблица значений игры (tables/<exe>.txt)
│  └─ ui/
│     ├─ Input.h/.cpp       # безопасный ввод с консоли
│     ├─ Menu.h/.cpp        # пункты меню
│     ├─ TableMenu.h/.cpp   # подменю таблицы
│     └─ PointerMenu.h/.cpp # подменю pointer scan
├─ cce.sln                  # решение Visual Studio
└─ cce.vcxproj              # проект Visual Studio
```

## Как пользоваться

1. Запусти `cce.exe`. Если запущена игра, для которой уже есть таблица, программа сразу предложит подключиться к ней. Иначе выведет список процессов в формате `PID | Name`.
2. Введи **PID** или **имя процесса** (`game.exe`). Если процесс не открылся, программа попросит ввести другой; `0` — выход.
3. После открытия процесса показывается таблица игры (если есть) и меню. В первой строке меню — сколько сейчас найдено адресов, их тип, сколько значений заморожено и сколько значений в таблице:

   ```
   [results: 0 int | frozen: 0 | table: 0]
   1. First Scan
   2. Next Scan
   3. Change value
   4. Freeze value
   5. Unfreeze value
   6. Show found addresses
   7. Save addresses to file
   8. Load addresses from file
   9. Table of pointers scan
   10. Save found value permanently (pointer scan)
   0. Exit
   ```

4. Введи номер действия и следуй подсказкам. Если ввести не число, программа просто спросит ещё раз. Пустой ввод там, где спрашивается значение или номер адреса, — отмена.

### Типичный сценарий

Допустим, в программе есть число (например, количество очков), и ты хочешь его изменить:

1. **First Scan** — выбери тип данных (чаще всего `int`) и введи текущее значение. Программа найдёт все адреса с таким значением (обычно их много).
2. Измени значение внутри целевой программы (например, очки выросли), вернись и сделай **Next Scan → Increased** (или *Exact Value* с новым числом). Список адресов сократится. Когда адресов останется 20 или меньше, список напечатается сам.
3. Повторяй шаг 2, пока не останется один-два адреса.
4. **Change value** — выбери нужный адрес по номеру и впиши своё значение.
5. При желании **Freeze value** — чтобы значение не менялось обратно.
6. **Save addresses to file** — сохранить найденные адреса, чтобы вернуться к ним позже в рамках того же запуска процесса (загрузка — пункт 8). После перезапуска процесса адреса будут другими.

### Если значение не видно

Например, полоска здоровья без цифр:

1. **First Scan** → тип (для здоровья чаще `float`) → **2. Unknown initial value**.
2. Получи урон в игре → **Next Scan → Decreased**.
3. Ничего не делай → **Next Scan → Unchanged**. Подлечись → **Increased**.
4. Повторяй, пока адресов не останется немного. Дальше всё как обычно: Change / Freeze / пункт 10.

Пока адресов слишком много (больше 5 миллионов), Change, Freeze, Show и Save недоступны — сначала отсей их через Next Scan.

Выход — пункт `0` (заморозка останавливается, дескриптор процесса закрывается). Если процесс-цель завершился, программа сообщит об этом и предложит дождаться его перезапуска.

## Значения, которые переживают перезапуск игры

Адрес значения в куче меняется при каждом запуске игры, а путь к нему — нет:

```
game.exe+1A2B3C  ->  10  ->  7C
```

1. Прочитать указатель по адресу `game.exe + 0x1A2B3C` (статический адрес внутри модуля — не меняется).
2. Прибавить `0x10`, снова прочитать указатель.
3. Прибавить `0x7C` — это адрес значения в этом запуске.

В Cheat Engine то же самое пишется как `[[game.exe+1A2B3C]+10]+7C`.

### Как сохранить значение (один раз)

1. Найди значение обычным сканом (**First Scan** / **Next Scan**). Важно взять **настоящий** адрес — тот, запись в который меняет значение в игре, а не копию для экрана.
2. **10** → номер адреса из результатов → имя (например, `Souls`). Программа сама найдёт цепочку указателей и сохранит значение:

   ```
   Done: Souls = 42389
   Pointer: DarkSoulsRemastered.exe+1C8A530 -> 10 -> 94
   Saved. Next time it is found automatically - see menu 9 (change / freeze).
   ```

### Дальше — без сканов

При каждом запуске программа сама подключается к игре, показывает таблицу с текущими значениями и включает сохранённые заморозки. Меню **9. Table** — изменить, заморозить, переименовать или удалить значение. Цепочку, найденную в другой программе (например, в Cheat Engine), можно добавить вручную: **9 → 3**.

### Как это устроено

Цепочек к одному значению обычно находится много. Показывается одна — самая надёжная (начинается в exe игры и идёт через маленькие смещения). Ещё до 15 штук хранятся в файле как запасные: при каждом запуске цепочки сверяются между собой, и если какая-то сломается, значение найдётся по остальным.

Если игра обновится, смещения могут сдвинуться — тогда значение нужно сохранить заново.

## Форматы файлов

### Сохранение адресов

Адреса сохраняются в `adres.txt` в рабочей папке. Первая строка — количество записей, далее по строке на адрес:

```
<адрес в hex> <тип> <размер в байтах> <значение>
```

Тип: `1` — short, `2` — int, `3` — float, `4` — double, `5` — byte, `6` — int64. Все записи в файле должны быть одного типа. Файлы, сохранённые старой версией программы, загружаются без изменений.

### Таблица игры

`tables/<exe>.txt` рядом с `cce.exe`. Одна запись на строку, колонки через `|`, запасные цепочки через `;`, последняя колонка необязательна:

```
# cce table: game.exe
Money | int | game.exe+1A2B3C -> 10 -> 7C ; game.exe+2B3C4D -> 8 -> 7C | freeze 99999
Health | float | game.exe+2B3C4D -> 18
```
