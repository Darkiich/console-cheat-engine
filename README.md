# console-cheat-engine
Консольный cheat engine с основным функционалом. Был написан для практики в языке C/C++

Запускать обязательно от имени администратора!!!!

## Следующий текст был написан используя ИИ, чтобы ускорить процесс написания документации к проекту

Консольный сканер и редактор памяти процессов для Windows — упрощённый аналог Cheat Engine. Написан на C/C++ для практики в работе с WinAPI, памятью процессов и многопоточностью.

Программа подключается к выбранному процессу, ищет в его памяти значения нужного типа, позволяет отфильтровать результаты несколькими повторными сканированиями, изменить найденное значение, «заморозить» его (постоянно перезаписывать) и сохранить найденные адреса в файл.

> ⚠️ Проект учебный. Используй его только на своих программах и процессах, которые тебе разрешено изменять. Вмешательство в чужое ПО, онлайн-игры и сервисы может нарушать их правила и закон.

## Возможности

- **First Scan** — первичный поиск значения в памяти процесса с выбором типа данных: `short` (2 байта), `int` (4 байта), `float` (4 байта), `double` (8 байт). Сканируются выделенные регионы памяти, доступные на запись (включая copy-on-write страницы модулей, где лежат статические переменные). Поиск идёт по выровненным адресам, как «Fast scan» в Cheat Engine.
- **Next Scan** — повторная фильтрация уже найденных адресов по условиям: увеличилось (*Increased*), уменьшилось (*Decreased*), точное значение (*Exact Value*), изменилось (*Changed*), не изменилось (*Unchanged*). Адреса, которые перестали читаться, отбрасываются.
- **Change value** — запись нового значения по выбранному адресу. Если адрес заморожен, заморозка продолжает держать уже новое значение.
- **Freeze value** — «заморозка» значения: фоновый поток каждые 50 мс перезаписывает все замороженные адреса. Замораживается текущее значение или то, которое введёшь. Заморозка не зависит от результатов скана: после нового First/Next Scan или загрузки из файла замороженные адреса продолжают работать.
- **Unfreeze value** — снятие заморозки с выбранного адреса.
- **Show found addresses** — список найденных адресов с текущим и предыдущим значением (показываются первые 100).
- **Save / Load addresses** — сохранение найденных адресов в файл `adres.txt` и загрузка их обратно.

После каждого скана печатается статистика: сколько найдено, сколько мегабайт прочитано, сколько было вызовов `ReadProcessMemory` и сколько времени это заняло.

Для `float` и `double` сравнение идёт с погрешностью (эпсилон `0.001`), чтобы учитывать неточность представления дробных чисел. Дробные числа можно вводить и через точку, и через запятую.

## Структура проекта

Проект разделён на две части: **core** — работа с памятью (ничего не печатает и не спрашивает у пользователя), **ui** — консольный интерфейс поверх core. Благодаря этому к ядру позже можно прикрутить другой интерфейс (например, GUI) без переписывания логики.

```
cce/
├─ main.cpp                 # точка входа: список процессов, выбор PID, запуск меню
├─ src/
│  ├─ core/
│  │  ├─ Win.h              # подключение windows.h + UniqueHandle (RAII-обёртка над HANDLE)
│  │  ├─ Value.h/.cpp       # типы значений (ValueType), Value, разбор и форматирование
│  │  ├─ Process.h/.cpp     # список процессов, открытие, чтение/запись памяти
│  │  ├─ Scanner.h/.cpp     # First Scan и Next Scan
│  │  ├─ Freezer.h/.cpp     # заморозка значений (один фоновый поток)
│  │  └─ AddressFile.h/.cpp # сохранение/загрузка адресов
│  └─ ui/
│     ├─ Input.h/.cpp       # безопасный ввод с консоли
│     └─ Menu.h/.cpp        # пункты меню
├─ cce.sln                  # решение Visual Studio
└─ cce.vcxproj              # проект Visual Studio
```

## Сборка

### Вариант 1. Visual Studio

1. Открой `cce.sln` двойным кликом.
2. Вверху выбери конфигурацию `Debug | x64` (или `Release | x64`).
3. Собери и запусти — `F5`. Готовый `cce.exe` появится в папке `x64/Debug/`.

### Вариант 2. Скачать .exe файл в Release
1. Заходим сюда - https://github.com/Darkiich/console-cheat-engine/releases
2. Нажимаем на console-ce.exe
3. После скачивания открываем от имени администратора!!!!

Кроме того, GitHub Actions собирает `cce.exe` при каждом push: вкладка **Actions** → нужный запуск → **Artifacts**.

## Как пользоваться

1. Запусти `cce.exe`. Программа выведет список процессов в формате `PID | Name`.
2. Введи **PID** процесса, с которым хочешь работать (число из левого столбца). Если процесс не открылся, программа попросит ввести другой PID; `0` — выход.
3. После открытия процесса показывается диапазон сканируемой памяти и появляется меню. В первой строке меню — сколько сейчас найдено адресов, их тип и сколько значений заморожено:

   ```
   [results: 0 int | frozen: 0]
   1. First Scan
   2. Next Scan
   3. Change value
   4. Freeze value
   5. Unfreeze value
   6. Show found addresses
   7. Save addresses to file
   8. Load addresses from file
   0. Exit
   ```

4. Введи номер действия и следуй подсказкам. Если ввести не число, программа просто спросит ещё раз. Пустой ввод там, где спрашивается значение или номер адреса, — отмена.

### Типичный сценарий

Допустим, в программе есть число (например, количество очков), и ты хочешь его изменить:

1. **First Scan** — выбери тип данных (чаще всего `int`) и введи текущее значение. Программа найдёт все адреса с таким значением (обычно их много).
2. Измени значение внутри целевой программы (например, очки выросли), вернись и сделай **Next Scan → Increased** (или *Exact Value* с новым числом). Список адресов сократится. Когда адресов останется 20 или меньше, список напечатается сам.
3. Повторяй шаг 2, пока не останется один-два адреса.
4. **Change value** — выбери нужный адрес по номеру и впиши своё значение.
5. При желании **Freeze value** — чтобы значение не менялось обратно.
6. **Save addresses to file** — сохранить найденные адреса, чтобы вернуться к ним позже в рамках того же запуска процесса (загрузка — пункт 8). После перезапуска процесса адреса будут другими.

Выход — пункт `0` (заморозка останавливается, дескриптор процесса закрывается). Если процесс-цель завершился, программа сообщит об этом и выйдет.

## Формат файла сохранения

Адреса сохраняются в `adres.txt` в рабочей папке. Первая строка — количество записей, далее по строке на адрес:

```
<адрес в hex> <тип> <размер в байтах> <значение>
```

Тип: `1` — short, `2` — int, `3` — float, `4` — double. Все записи в файле должны быть одного типа. Файлы, сохранённые старой версией программы, загружаются без изменений.
